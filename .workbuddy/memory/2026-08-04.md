## WPS 表格字段映射工具（麒麟 Linux 版）
- 生成单文件 PyQt5 桌面程序：`wps_table_mapper.py`
- 功能：源/目标 Excel 上传、QTableWidget 映射配置（默认20行）、三种填入方式（直接/合并/拆分复制）、日期自动转 `YYYY.MM`、整表复制另存 .xlsx（保留格式/公式）。
- 技术点：openpyxl 读源（data_only）写目标（保留样式）；.xls 走 xlrd 回退；合并复制用 MultiSelectDialog 多选 2~5 源列；行操作 + / - 用 sender() 动态定位行，避免索引错位。
- 校验：日期转换逻辑单元测试全部通过；py_compile 语法 OK。
- 说明：openpyxl 不原生支持 .xls，.xls 目标表无法保留格式，输出为新 .xlsx 并提示用户。

## 麒麟 Linux 打包（PyInstaller）
- 新增 `build_kylin.sh`（PyInstaller --onefile --windowed，--collect-all PyQt5/openpyxl，隐藏导入 xlrd）与 `打包说明.md`。
- 关键限制：PyInstaller 不能跨平台编译，必须在 Linux（推荐直接在目标麒麟机）打包；且需与运行机同 CPU 架构（amd64/aarch64）。
- 本机 WSL 被安全策略禁用，无法在此实际构建 Linux 二进制，仅交付脚本+说明。
- 运行依赖系统库 libgl1；GLIBC 版本不匹配时需在目标机重新打包。可选 AppImage 提升跨发行版兼容。
- 离线安装：新增 `download_deps.sh`（联网同架构机 `pip download` 到 wheels/）与 `offline_install.sh`（离线机 `pip install --no-index --find-links=./wheels`）。
- 离线最优解：直接在联网同架构机跑 build_kylin.sh 出单文件二进制，目标机零依赖。也可挂麒麟 ISO 用 apt-cdrom/本地源离线装 python3-pyqt5。
- 目标机架构确认：麒麟 V10 SP1 + 华为 Kirin 9000C = **aarch64(ARM64)**。PyInstaller 二进制必须在该 aarch64 环境（即麒麟本机或 aarch64 VM）构建，x86_64 Windows 无法产出可用的 ARM64 二进制。
- Windows 验证可行：源码跨平台，无需改 Linux 版；同一 .py 在 Windows 装 pyqt5/openpyxl/xlrd 后 `python wps_table_mapper.py` 即可验证全部功能。已生成 demo_source.xlsx/demo_target.xlsx 及 verify_logic.py 做无界面逻辑验证（日期转换/合并/拆分均正确）。

## 关键 bug 修复：脚本启动报"缺少 PyQt5" 实为导入语句写错
- 真因：之前把 `QIcon, QPixmap` 加进了 `from PyQt5.QtWidgets import (...)`，但 QIcon/QPixmap 属于 `PyQt5.QtGui`；导入时抛 `cannot import name 'QIcon' from 'PyQt5.QtWidgets'`，被 `except ImportError` 捕获后误报"缺少 PyQt5"。已挪到 `from PyQt5.QtGui import QFont, QColor, QIcon, QPixmap`。
- 同时发现用户 Windows 存在**多 Python PATH 冲突**：`python` 指向 WorkBuddy 托管 3.13.12（无 PyQt5），`pip` 指向 `C:\Users\b2522\AppData\Local\Programs\Python\Python313\python.exe`（Python 3.13.7，已装 PyQt5/openpyxl/xlrd 全齐）。
- 修复措施：① 把 PyQt5/openpyxl 的 except 改为打印**真实错误 + 当前 sys.executable**，避免误导；② 新增 `run_windows.bat`，用 Python313 绝对路径运行，不受 PATH 影响。
- 验证：`Python313\python.exe -c "import wps_table_mapper"` 输出 IMPORT_OK。Windows 上双击 run_windows.bat 即可启动（GUI 需桌面会话）。麒麟上仍用 `python3`。

## 又修一个导致启动崩溃的真 bug（用户报“方法1/2都不行”）
- `_tab_icon` 是模块级函数，但 `_build_ui` 里写成了 `self._tab_icon(...)`（当方法调用）→ 启动即 `AttributeError: 'MainWindow' object has no attribute '_tab_icon'`。已改为模块级调用 `_tab_icon(...)`。
- 用 `QT_QPA_PLATFORM=offscreen` 在 Python313 上做了**整窗构建冒烟测试**（import + MainWindow() + show + processEvents），输出 `UI_BUILD_OK; merge控件齐全`，确认两个标签页与合并页控件均正常。
- 用户要求改环境变量：用 PowerShell `[Environment]::SetEnvironmentVariable("PATH",...,"User")]` 把 `Python313` 与 `Python313\Scripts` 前置到**用户级 PATH**（可逆、不影响系统 PATH；WorkBuddy 用绝对路径调 python 不受影响）。但 `reg` 被安全策略禁用，无法回读确认；已提示用户开新终端 `python --version` 验证（应显示 3.13.7）。
- run_windows.bat 增加 `if errorlevel 1 pause`，异常时停留显示错误，避免一闪而过。
- 结论：之前"方法1/2都不行"实为 `_tab_icon` 崩溃（被误当成缺 PyQt5 / 或一闪而过没看清）；代码修好后 bat/绝对路径均可正常启动。
